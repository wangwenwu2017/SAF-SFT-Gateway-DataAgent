# Science Agent Factory 编码约定

本文件适用于 `science-agent-factory/` 及其所有子目录。执行代码新增、修改、重构或删除时，都必须遵守下面的约定。
仓库级约定（结构、GitHub 工作流、密钥与忽略项）见仓库根 `AGENTS.md`。

## 代码文件职责先行与文件头同步

### 1. 编码前：先定义文件职责

在创建或修改代码文件之前，先明确并记录以下信息：

- 文件或模块在系统中的唯一职责，以及它不负责的边界。
- 主要公开接口，包括导出的类、函数、类型、命令或协议。
- 输入，包括函数参数、配置、环境变量、文件、数据库记录、消息或制品引用。
- 输出，包括返回值、异常、文件、事件、状态变化或外部调用结果。
- 副作用与运行边界，包括文件系统、SQLite、网络、SDK、子进程、QEMU、权限和并发行为。

如果无法清楚说明这些内容，应先完成接口和职责设计，不得直接开始堆叠实现。

### 2. 编码时：同步维护代码文件头

- 每个代码文件都必须在文件开头包含与当前实现一致的模块级说明。
- Python 文件使用模块级 docstring，并放在 `from __future__` 和其他导入之前。
- 生产代码文件头统一包含：`模块用途`、`主要接口`、`输入`、`输出`、`副作用与边界`。
- 测试代码文件头统一包含：`测试目的`、`被测接口`、`输入与夹具`、`预期结果`。
- `__init__.py`、包入口、CLI、迁移、测试辅助模块也属于代码文件，不能省略说明。
- 英文术语或简称可以保留，但首次出现时应给出中文解释。
- 文件头描述必须反映当前真实行为，不得把计划功能、尚未修复的设计目标或未经保证的安全属性写成既成事实。
- 新增、删除或修改接口、输入输出、外部副作用、权限或职责时，必须在同一次变更中更新文件头。

文件头用于说明模块级契约，不应逐行复述实现。私有辅助函数可以按职责分组描述，公开接口不得遗漏。

### 3. 编码后：执行一致性检查

完成代码后至少进行一轮文件头检查：

1. 确认所有新增和修改的代码文件都有模块级说明。
2. 对照实现逐项核对职责、主要接口、输入、输出和副作用，删除过时描述。
3. 确认文件头没有扩大实际权限、隐藏失败条件或承诺实现中不存在的保证。
4. Python 代码运行：

   ```bash
   uv run pytest -q tests/test_module_documentation.py
   uv run ruff check src tests
   ```

5. 根据改动范围运行相关测试；合并或交付前运行完整测试：

   ```bash
   uv run pytest -q
   ```

代码实现与文件头说明不同步，或文件头完整性检查未通过，均视为工作尚未完成。

## Git 与 GitHub 工作流

本子项目位于单体仓库 `SAF-SFT-Gateway` 内（`science-agent-factory/`）。Git 操作作用于**仓库根**，
统一遵循根 `AGENTS.md`：

- `origin` 指向 GitHub `wangwenwu2017/SAF-SFT-Gateway`，默认分支 `main`。
- 工作区状态、提交范围以及 `.env`、`configs/server.yaml`、`configs/local.yaml` 等忽略项，均以仓库根为准。
- 禁止强推、变基或删除已推送的共享历史；回退使用 `git revert` 形成可审计的新提交。
- 推送前在仓库根运行 `make check`，或在本子项目运行完整门禁（见上一节）。
- `scripts/git_sync.sh` 仅作为可选的本地双工作区同步工具保留；其 `saf.role` 约定不再是本仓库的强制流程。
